# Starting from an Empty Folder

Use this after the user chooses a template. The goal is a useful first working
loop, not an empty directory tree.

## Before applying

Ask one question at a time:

1. What real outcome, responsibility, topic, or action system should this
   knowledge base support first?
2. What existing fact, note, task, or source should seed it?

Do not demand a complete taxonomy. One real example is enough.

## Apply the selected template

Preview, obtain confirmation, apply, and verify through the onboarding workflow.
Use `minimal` unless the user explicitly wants the full periodic template set.

## Create the first useful content

### Memos

- Create or open today's daily note.
- Add one real bullet or task under the configured Daily Record header.
- Do not invent theme folders or tags before the user needs retrieval beyond time.
- If full density is enabled, establish the first weekly review checkpoint.

### PARA

- Create one active Project when the user has a concrete outcome.
- Create one Area only for an ongoing responsibility.
- Create one Resource only when reusable source material already exists.
- Put a new unprocessed item in Capture.
- Put the user's first draft or synthesis in Express.
- Add one concrete next action to the Project or current periodic note.

### IPO

- Add one real source to Input.
- Create one Theme that states the current judgment or question.
- Create an Output note only when a deliverable is genuinely intended.
- Record the next transformation step from input to theme or theme to output.

### GTD

- Capture the user's real open loops in Inbox.
- Clarify at least one item into an Action or Project.
- Put non-actionable support material in Reference.
- Establish the first review checkpoint.

## Finish criteria

Onboarding is complete when:

- the template and Skill verify successfully;
- the user can name the primary entry point;
- at least one real note or task exists in that entry point;
- the next capture or review action is clear.

Do not generate fictional projects, responsibilities, sources, or tasks merely
to make the knowledge base look populated.
