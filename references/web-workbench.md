# 在 AI 客户端中打开项目工作台

用户希望查看或编辑当前本机项目，或通过对话展示某个日历视图时，使用同一套 Aino Desktop Web 工作台。无需 MCP Apps；不要生成不存在的 MCP 配置或另一套 HTML 界面。

## 先确认运行环境与项目

- 必须有用户电脑上的命令执行能力。核对客户端提供的项目绝对路径及终端工作目录；多项目时使用用户本次指定的项目。始终显式传 `vault="绝对路径"`，避免环境变量或父级库标记把请求导向其他库。
- 云端聊天项目、仓库 URL、云端沙箱目录不是用户电脑目录。没有本地工具时，给出本机启动命令，不能声称已经启动；客户端是否能打开本地地址也需实际验证。
- `web` 需要 Node.js 24+ 和包含 Web 资源的 CLI。此能力目前属于开发候选，不能假设公开 npm 版本已包含它。优先使用用户已安装或指定的候选 CLI，先读其 `help`，确认存在 `web`；缺少运行时按真实报错处理，不循环重装同一个旧 npm 版本。
- 保持同一个 CLI 来源执行后续操作，包括 Skill 安装；不要启动候选后又用旧版 `npx ...@latest` 覆盖候选 Skill。

## 启动与打开

默认流程是：**启动或复用当前库的服务 → 返回可点击的「打开 Aino Web」链接 → 用户点击**。服务实际监听且库身份确认后，在回复中用 `[打开 Aino Web](服务实际输出的 URL)`，简短说明“服务已就绪，点击打开”；保留用户请求的视图、筛选和分组。启动时保持 `open=none`（默认值）。链接点击后的打开位置由宿主决定，不能假定所有客户端都内嵌。已有正确库的服务直接返回链接，不重复启动。

宿主已提供网页打开工具时，可额外自动展开真实 HTTP 页面；这不是必经步骤，缺少工具或调用失败仍返回可点击链接，不反复搜索、要求用户修改全局权限或生成替代 HTML 预览。`open=browser` 会唤起系统默认浏览器，仅在用户明确要求时使用。

统一入口名称为 **打开 Aino Web**。用户使用这个名称时，直接执行下方流程；客户端支持快捷指令时，快捷指令内容使用下方提示词，仍由同一个 LifeOS Skill 处理，不复制一套客户端专属启动逻辑。

`aino web`、`lifeos web` 都触发此入口。在 Aino Desktop 外的桌面 AI 客户端中，用户仅说 `LifeOS` 也默认启动或复用当前库并附上链接，无需先追问是否要打开；仅说产品名时使用 `view=home`。同时有任务、编辑或视图请求时按实际意图选择视图。宿主判断使用明确的客户端上下文或原生工具元信息，不通过 `ps` 判断电脑是否安装或运行了 Desktop。缺少本机执行能力、库路径或用户明确不要启动时，按实际限制处理；不把未知目录自动初始化成知识库。

固定网页入口只负责打开已有服务，不能在服务停止时自行执行本机命令。添加收藏或网站小程序前先验证目标服务属于正确项目；不要把某个测试库的临时地址配置成所有项目通用入口。需要启动或切换项目时使用 Skill 入口；没有本地执行能力时明确说明这一限制。

打开后优先读取客户端当前网页工具提供的页面状态或截图。不要为核对库名额外启动无头浏览器、安装 Playwright 或生成渲染脚本；另一个浏览器的结果不能证明客户端内已打开。无法读取客户端页面时，区分“服务库身份已核对”“已请求客户端打开”和“页面显示已确认”，只报告实际取得的证据。

客户端项目路径的传递链路是：客户端提供本机项目目录 → Skill 核对绝对路径 → CLI 的 `vault=` → Node 绑定该库 → Web 从服务端 bootstrap 读取库路径。不要从网页 URL、聊天标题或客户端项目名称推断磁盘目录。切换客户端项目后应重新执行这条链路；已经打开的页面不会自动切到新项目。

用户可以直接对客户端说：

> 使用 LifeOS Skill 打开当前项目的 Aino Web 工作台。核对本机项目目录，用包含 Web 能力的 CLI 启动或复用这个库的服务，返回可点击的「打开 Aino Web」链接。如果无法启动，请说明原因。

如果客户端只提供云端项目，需用户指定本机目录并在本机启动服务；云端项目地址不能直接转换成磁盘路径。客户端切换项目的自动事件同步需要对应宿主提供接口，当前不宣称已支持。

以下 `lifeos` 表示已核验的 CLI 入口；若候选使用 `node /path/to/lifeos.mjs`，替换命令前缀即可。

```bash
lifeos web vault="/absolute/path/to/project" port=4318 view=calendar subview=month
```

命令会持续运行并输出本地 URL。普通产品启动不依赖 `ps` 或本仓库的 `dev-gate`；不要把开发机资源管理工具当作用户安装前提。通过客户端已有的后台任务／持续终端能力保留进程，遵守所在环境的服务资源规则；不要等它自然退出才打开页面。Ctrl+C 停止服务。不要擅自创建开机启动项。

本机开发与验证仍须遵守当前环境的资源闸门规则；这与产品接入要求分开。如果所在环境要求通过资源闸门启动，闸门失败就是本次启动失败。客户端提供正式的单次授权入口时可按其流程申请；仍被禁止时停止，报告具体限制。不要跳过闸门、关闭进程检查、修改锁目录，或改用未受管理的后台进程冒充成功。没有实际监听的服务不能继续宣称已打开工作台。

检查回环地址时，请求须直接到本机，例如 `curl --noproxy '*' http://127.0.0.1:<port>/health`；不要把代理返回的错误当作本地服务响应，也不要修改系统代理配置。服务身份优先从已核对的启动命令或客户端当前页面确认。不要为打开页面提取 Cookie、会话令牌或写临时凭据文件；网页由本地服务完成自身会话初始化。

仅复用已有启动记录或当前页面已确认属于当前项目的服务；无需为了返回链接枚举系统进程。`/health` 只证明服务存活，不能证明库身份。已有服务库身份不明时选择另一个空闲端口，不停止其他任务、不直接复用端口上的未知服务。当前 CLI 不提供自动跨进程发现／复用功能。

使用服务实际输出的 URL，不把磁盘路径拼成 `?vault=`。URL 中没有切库授权；不同库由 Node 创建各自的服务实例。标题栏的当前库名称菜单或左侧栏库名按钮可通过本机目录选择器切库；其他打开页面仍连接原库。macOS 目录选择已实现，其他平台暂用显式 CLI 路径启动。

点击库名后，选择器出现在运行 Node 服务的电脑上，不一定嵌在客户端网页中。按钮等待期间显示沙漏；取消选择会恢复按钮并保留当前库。远程或无桌面环境使用显式 `vault=` 启动对应库，不能把网页无响应当作已经切换成功。

- WorkBuddy：默认返回可点击链接。若当前工具列表提供内置 `present_files`，可额外传 `{"files":["服务实际返回的 HTTP URL"],"cwd":"当前库绝对路径","explanation":"打开 Aino Web 工作台"}` 请求自动展开；按实时 schema 调用。HTTP URL 对应内置 Browser，本地 HTML 文件对应文件预览。缺少工具不阻塞链接交付。入口依据：[官方更新日志](https://www.codebuddy.cn/docs/workbuddy/Changelog)；HTTP URL 与 cwd 参数已核对 WorkBuddy 5.9.3 的内置工具定义，页面呈现仍需实测。
- 豆包工作：默认返回可点击链接；宿主提供网页工具时可额外展开。核验实际页面位置和对应库，不把输出链接算作已内嵌。
- Cherry Studio：默认返回可点击链接。需要额外自动展开时，先读取内置 `cherry-browser` Skill 的实时 API 文档，再在当前会话右侧浏览器导航实际本地 URL。`client=cherry` 默认使用完整浏览器高度，不预留底部输入框空间；不要传旧的 `bottom-inset=144`。当前普通助手没有本地 Shell／Skills 时，明确缺少启动能力；可打开已经核对正确库的现有服务，不能把“打开 aino web”解释为访问 `aino.ai` 等猜测的公网地址。不要重置浏览器绕过工具错误。
- ChatGPT／Codex：默认返回可点击链接；若当前会话已注册本地 `aino_web_open` 工具，可额外调用它主动打开配置库的面板；参数可指定视图、子视图、筛选及分组。它与普通 Web 启动复用同一个 Node 实现，不是另一套编辑器。工具只请求打开，仍须核对实际呈现。没有工具时不编造调用；有本机执行能力时使用普通 Web 流程，否则给出本机启动命令。普通云端聊天不能自动访问用户电脑的回环地址；具体配置见候选 CLI 的 `presentation=panel` 接入说明。
- Codex／Claude Code 终端或不支持内嵌的客户端：同样返回链接；用户要求自动打开时才调用系统浏览器，并说明实际位置。

首次打开默认收起左右侧栏，之后保留用户操作。主题／语言默认跟随可获取的系统或浏览器偏好；宿主未向网页提供的设置不能假称已同步。

## 把对话意图映射到原视图

主视图：`view=editor|home|calendar|random-walk`。

日历子视图：`view=calendar subview=day|week|month|tasks|timeline|kanban|agenda|quadrants`。

```bash
lifeos web vault="/absolute/path/to/project" view=calendar subview=kanban group-by=priority query="tag:#工作"
```

- `query=` 复用原日历搜索语法，叠加已有筛选，可在原界面清除；不意味着替换用户所有已有筛选。
- `group-by=dueDate|priority|status|tag` 只支持 `view=calendar subview=kanban`。
- 子视图、查询、分组作为这次打开的临时意图；用户主动切换仍按原规则保存偏好。
- 不支持独立日期范围、精确笔记深链或任意集合参数时，不编造选项。使用现有界面完成，并说明实际选择。

启动本地工作台不需要修改、移动或迁移用户笔记。复用原编辑器与侧栏，不因 Web 页面可打开就声称所有 AI、邮件、日历连接器或三客户端验收已完成。

## 对话后的精确结果页与文件保存

- 日期跳转：`lifeos web vault="/absolute/path/to/project" view=calendar subview=month date=2026-11-08`。日期采用本地 `YYYY-MM-DD`，拒绝不存在的日期。
- 文件跳转：`lifeos web vault="/absolute/path/to/project" view=editor file="Reports/本周复盘.md"`。`file` 必须是库内相对路径，不接受绝对路径或 `..`。
- 已有正确库的服务时直接复用其地址，附加 `?view=editor&file=<编码后的相对路径>`；不重复启动进程。日历保留 `subview`、`date`、`query`、`group-by`。编码每个参数，不把 `#` 或 `&` 当作 URL 分隔符。
- AI 按钮复制的是同一业务请求和明确材料，不代表自动读取了全部原文。没有本机工具时只基于已附数据回答，并说明无法读取的部分。
- 需要落盘时先展示预览并征得同意；用同一候选 CLI 的 `read` 核对目标，再 `create` 新笔记或 `append` 补充已有笔记，显式传 `vault=` 与 `path=`。用参数数组传正文，不直接拼接 shell；不要自动覆盖已有文件。
- 只在写入命令成功后返回准确、可点击的结果链接；宿主支持时可额外自动展开。Web 通过原 Node 文件事件刷新索引和编辑器，未保存编辑沿用原冲突保护；不宣称报告自动回填到 AI 复盘面板。

## 在 Aino Web 或 Desktop 中继续 AI 对话

新启动的工作台默认支持本机 Codex CLI，AI 模块仅在用户打开对话时按需启动；`ai=none` 显式关闭，保留查看、编辑和复制给宿主 AI。需要本机已安装、已登录 Codex，不会使用宿主当前对话或其模型额度。

AI 按钮主区域直接执行当前去向，小箭头才打开菜单；菜单顺序固定为“在 Aino Web 中继续”“在 Aino Desktop 中继续”“复制给宿主 AI”。Web 去向展开复用的 Aino 右侧对话栏，带入草稿与上下文，由用户检查后发送；Desktop 去向请求本机桌面端接收。复制成功要提示用户手动粘贴并发送，不宣称已填入宿主输入框。默认侧栏仍隐藏，首次使用按提示安装库内 LifeOS Skills。关闭或刷新页面会中断当前页面拥有的 CLI 连接，不能承诺任务继续在后台执行。

右侧 AI 对话栏也提供“在 Aino Desktop 中继续”。它交接可见的文字对话、草稿和文件上下文，不继承宿主会话、模型账户或工具执行状态。桌面端必须包含交接协议的新版候选；已安装旧版不保证可用。出现“已请求打开”只表示发起请求，必须核对 Desktop 是否实际收到，不能当作交接成功。不要为了验证而改系统默认协议注册或替用户自动发送。

已运行的旧服务不自动升级能力。先保存编辑内容，使用同一候选 CLI 重新启动服务后再刷新页面；不把 URL 参数当作服务端授权开关。Web 跟随 LifeOS CLI 授权，不引入 Desktop 激活页面。

## 服务何时停止

当前知识库名称始终显示在工作台标题栏，点击可切换知识库或“停止工作台”。停止前先保存笔记；其他页面仍连接或任务仍在运行时会拒绝停止。所有页面断开后保留 10 分钟；期间重新打开或刷新可继续使用。到期仍有任务时等待任务结束再退出。未曾打开的服务也会在空闲 10 分钟后退出。停止后需要再次通过 LifeOS Skill 启动，旧链接不会自动启动服务。复用地址前须确认服务仍可用且绑定的是当前库，不能把其他库的旧链接当作当前库。
